## 1. QA（本機）

順序固定，前一步沒過不要往下：

1. **建置**：`python3 build.py --shots`。看終端機的佔位字清單。
2. **自動檢查**：`python3 "<skill>/scripts/qa_page.py" <專案資料夾>`。
   - 預設量 1440／1024／390 三個寬度、活動頁與感謝頁。
   - ❌ 全部要清掉才交件。
   - ⚠️ 逐條判斷，要不要處理列給使用者。
   - ℹ️ 的報名區塊數字拿去更新 `layout.json`。
   - 能抓的：橫向溢出、手機貼邊、禁用樣式（平滑捲動、pretty、balance、keep-all）、標題與表單欄位標籤的孤字、並排對齊、插圖浮空與同組比例、報名色誤用、錨點、內容欄對齊、報名區塊高度、佔位字、字型沒載入、PNG 過大。
3. **眼睛看**：打開 `out/_shots/*-desktop.jpg`、`*-mobile.jpg`（或用瀏覽器開 `out/preview.html` 縮到三個寬度）。腳本抓不到的：
   - 角色走樣（照 pinfriends 的 QA 三點）。
   - 漸層、光暈、白條（pitfalls D7）。
   - 同組插圖的角色大小、服裝是否一致（D2）。
   - 配色是否符合票上的色彩方向。
   - 第一屏（手機）看不看得到主標與報名按鈕。
4. **同類全掃**（Cofit 案教訓：第 3 段插圖浮空只修了兩張，隔天第 4 段三張被抓到一樣的問題）：
   - 每修一個問題，先找病因在哪一層（原圖、共用 CSS、產生器、共用片段），把同層所有實例列出來一起修。
   - 修完重跑 2、3。
   - 回報時寫「掃過哪些地方」。
5. **文案定稿檢查**：語義檢查（口徑、時態、名詞一致、日期星期、數字出處）與**全文逐句語感通讀**兩道都做完，才能說「可以定稿」。
   - 活動頁容易漏的：同一個活動的稱呼（說明會／講座）、日期寫法、CTA 文字種類、刪字修孤字後語意有沒有變。

## 2. 交付物與回報格式

| 交付物 | 位置 | 給誰／做什麼 |
|---|---|---|
| 上稿指南（HTML，含複製按鈕、欄位表、尺寸表、預期畫面、驗收清單） | `out/上稿指南.html` | Hsing 照著貼 |
| 貼上用程式碼 | `out/instapage/1_head.html`、`2_body.html`、`3_signup-block.html`、`4_footer.html`、`ty_2_body.html` | 貼 Instapage |
| 上傳用（OG 兩份＋SEO 文字） | `out/上傳用/` | Instapage 頁面設定 |
| OG、社群圖（PNG＋向量 PDF） | `out/images/` | 社群與設計師（.ai 用 PDF 另存） |
| 本機預覽 | `out/preview.html`、`out/preview_thankyou.html` | 看版面 |
| QA 報告 | `out/qa_report.json` | 留底 |
| 交接 | 專案根 `交接.md` | 下一個 session |

**回報格式**（第一段永遠是要 Hsing 判斷的事，不是成果）：

```
現在是 YYYY-MM-DD HH:MM（Asia/Taipei）。

⚠️ 需要你判斷的（N 項）
1. {哪一句／哪個設計}｜{為什麼要你決定}｜建議：{…}
（沒有就寫「⚠️ 無」）

QA：qa_page.py ❌ 0／⚠️ N（列出 ⚠️），1440／1024／390 都看過截圖；掃過的同類：{…}

這次改了什麼／要重貼哪幾段：{例：Head＋Body 要重貼，Footer 不用}

檔案：{完整路徑}（並執行 open -R 或 open 資料夾）
```

改了哪幾段程式碼，一定要寫清楚「要重貼哪幾格」：Hsing 每一批都靠這一句知道要做什麼（pitfalls F5）。同時更新 `交接.md`。

## 3. 上稿（Hsing 在 Instapage 後台做）

- Instapage 要 Hsing 自己登入，Claude 不代登入、不輸入密碼。
- Hsing 登入後要 Claude 在 Chrome 裡操作時：
  - 建頁、改設定可以做。
  - **每一次發布都要先問**。
  - 正式網址的發布由 Hsing 按。
- 步驟照上稿指南：
  1. 複製來源頁（nova-webinar），先用測試網址。
  2. 刪掉表單以外的區塊。
  3. 報名區塊照第五節設定尺寸。
  4. 表單照第二節核對欄位、接 Zapier、設導向、改按鈕文字。
  5. 貼 Head／Body／Footer。
  6. 設手機版（不要按 Regenerate）。
  7. 換 SEO 標題、描述與社群縮圖。
  8. 發布到測試網址。
- 感謝頁要先發布，活動頁表單的導向清單裡才選得到（pitfalls B6）。

## 4. 上線檢查

Hsing 說「上稿了」「發布了」之後，一律跑：

```bash
python3 "<skill>/scripts/check_live.py" events.alleypin.com/<活動頁> --thankyou events.alleypin.com/<感謝頁> --project <專案資料夾>
```

它只讀線上原始碼，不送出表單。會檢查：
- 標題、描述、OG、X（Twitter）卡片是不是這次的。
- og:image 是不是 1200×630。
- 收錄設定（只報現況）。
- Head／Body／Footer／報名區塊程式碼是否完整（有沒有被截斷、是不是舊版）。
- 有沒有平滑捲動或 pretty。
- 是否為原生表單、有沒有接 Zapier，以及 Zapier 有沒有漏對應的欄位。
- 送出後實際落點（跟著 route 轉址判斷，不信 `url=`）。
- 欄位名稱、順序、必填、選項、勾選文字、按鈕文字跟 `_mock_form.html` 比對。
- UTM 隱藏欄位。
- 編輯器區塊數量對不對、有沒有來源頁留下的文字（B11）。
- 報名區塊兩個元件的位置尺寸跟 layout.json 比（B13）。

2026-10-06 對 Cofit 頁實跑抓到 7 項：
- 沒接 Zapier。
- 送出後跳到 nova 的感謝頁。
- 第 8 欄、科別、勾選文字、按鈕文字都還是 nova 版。
- 活動頁 Head 是舊版（只缺感謝頁用的樣式，不影響活動頁 → ⚠️）。
- 加上之後補的三項檢查又抓到：感謝頁留著 nova 的手機版區塊（Nova 裕利回饋文案）、活動頁 twitter:description 是感謝頁的、報名區塊兩個元件位置沒照尺寸表（報名須知右偏 52px）。

腳本沒辦法做、要人做的：
- **送一筆測試名單**：送出表單＝真的產生一筆名單，要 Hsing 自己送，或明確同意後才做。
  - 看 Leads、Zapier Zap History 都有這筆。
  - 看有沒有落到這次的感謝頁。
  - 驗收完清掉或標註（B9）。
- **手機實機**（iPhone Safari）：
  - 點每一顆報名按鈕，約 0.3 秒捲到報名須知、停下後馬上能滑。
  - 點輸入框不會放大。
- **分享預覽**：把網址貼到 LINE 給自己，看標題、描述、縮圖是這次的（LINE 會快取，改過要等或加參數）。

結果照「回報格式」列給使用者。後台設定是使用者的權限：列出要改哪一格、改成什麼，不要代改。
