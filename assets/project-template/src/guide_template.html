活動頁：貼 3 段程式碼＋只建 1 個區塊（報名須知＋原生表單）。感謝頁：貼 3 段程式碼、不建區塊。程式碼都在第八節，按「複製」直接貼。

一、整頁結構：程式碼貼哪裡

Instapage 的頁面設定（右側 Page Settings → HTML/CSS）有 Head、Body、Footer 三格，都是整頁共用。上線時它們的位置是固定的（2026-10-05 拆 nova-webinar 上線原始碼確認，Cofit 頁上線驗證）：

Head：放在 <head> 裡 → 貼 1_head.html（字型＋全部樣式，含表單外觀）
Body：插在頁面一開頭、所有區塊之前 → 貼 2_body.html（{{BODY_LIST}}）
編輯器裡唯一的區塊：報名須知（左側欄拖一個 HTML 元件，貼 3_signup-block.html）＋ Instapage 原生表單
Footer：插在所有區塊之後 → 貼 4_footer.html（頁尾）

所以只有表單那一段需要在編輯器裡真的建區塊；它前面的段落放 Body、後面的頁尾放 Footer，剛好夾住它。Body、Footer 的段落高度由內容自己撐開，不用在後台設高度。

注意：Head、Body、Footer 的程式碼在編輯器和預覽模式都看不到（編輯器裡只會看到表單那一個區塊），一定要發布才看得到。所以先發布到測試網址。

二、表單：欄位手動建，外觀用程式

為什麼表單不能用程式寫

  • Instapage 原生表單送出時，會附上一組由 Instapage 簽章的表單設定（lpsSubmissionConfig），和一份 Zapier 欄位對應（zapier2-integration，依欄位名稱一對一對應）。程式寫的表單拿不到這個簽章，名單進不了 Instapage Leads，也不會觸發 Zapier。
  • 官方說明也寫明：用程式嵌入的表單不會跟原生整合、名單收集、通知信連動，也不算進轉換。

三、驗收清單

每一項的「沒過」長得跟「過了」不一樣，打開網址一眼就看得出來：

1. 樣式有載入標題是設計稿的字型、表單是白底圓角卡片＋報名色膠囊按鈕。
沒過：標題是一般黑體、表單是 Instapage 預設的方形欄位與藍色按鈕 → Head 沒貼到。
2. Body 有出現、滿版表單上方依序有 {{BODY_LIST}}；有底色的段落都延伸到瀏覽器邊緣；拉窄視窗不會出現左右捲軸。
沒過：一打開就是報名須知和表單 → Body 沒貼到；或頁面下半段缺了 → Body 被截斷（見第九節）。
3. 三段銜接最後一段 → 報名區塊 → 頁尾之間沒有白縫、沒有互相蓋住，左右對齊同一條內容欄。
4. 名單有進來送一筆測試資料 → Instapage 的 Leads 看得到；Zapier 的 Zap History 也有這筆，欄位都對得上。
5. 送出後到感謝頁轉到這次的感謝頁：KV（「感謝您的報名！」＋同一張插圖＋報名後須知）→「更多 AlleyPin 資訊」三張卡片（三個連結都點得開）→ 頁尾。
沒過：跳到別檔活動的感謝頁 → 送出後導向還是來源頁的。
6. 報名按鈕錨點頁面上每一顆報名按鈕，點了約 0.3 秒捲到報名須知，停下後馬上可以滑動。
沒過：快到時拖很久才停、期間滑不動 → Head 裡有 CSS 平滑捲動（scroll-behavior），重貼最新的 1_head.html。
7. 手機用手機打開：第一屏看得到標題和報名按鈕；點輸入框時頁面不會被自動放大。
8. 分享預覽把網址貼到 LINE 給自己：標題、描述、縮圖都是這次活動的，不是來源頁的。X（Twitter）卡片的描述是另一組設定，也要對（check_live.py 會比對）。
9. 手機沒有殘留用手機看感謝頁與活動頁：頁尾之後、表單前後沒有來源頁的舊文字或空白大塊。

四、活動頁上稿步驟

  1. 在頁面列表把 {{SOURCE_PAGE}} 複製一份（Duplicate），改名，網址先用測試網址（例如 {{TEST_SLUG}}）。
  2. 開編輯器，刪掉表單以外的所有區塊；表單所在的區塊裡，表單以外的元素也全部刪掉。桌機刪完切到 Mobile 檢視再檢查：只在手機顯示的元素在桌機看不到。
  3. 報名區塊：照第五節設定高度和背景色。從左側欄拖一個 HTML 元件進來（點開是空白的），按 Edit 貼上 3_signup-block.html，照第五節設位置與尺寸；表單也照第五節設位置與尺寸。
  4. 表單：照第二節核對欄位、接 Zapier、送出後導向這次的感謝頁、按鈕文字。
  5. 右側 Page Settings → HTML/CSS：Head 貼 1_head.html、Body 貼 2_body.html、Footer 貼 4_footer.html。
  6. 手機版：切到 Mobile 檢視，照第五節「手機」欄設定區塊高度和兩個元件的位置。不要按 Regenerate：會清掉手機版的所有手動設定。
  7. SEO 與社群：複製來的頁面標題、描述、社群縮圖都還是來源頁的，三個都要換（第七節）。
  8. 發布到測試網址，照第三節逐項檢查。

測試期間的名單：測試資料會進 Instapage Leads，也會經 Zapier 流進後面的試算表或 CRM，驗收完記得清掉或標註。

九、圖片：都寫在程式碼裡，不用上傳

  • 頁面上的圖（KV 插圖、場景圖、講者照片、logo）都轉成 WebP 再直接寫進程式碼（base64），都不用上傳到 Instapage。唯一要上傳的是社群縮圖，因為那是 Instapage 設定欄位，只收檔案。
  • 代價是程式碼變長：2_body.html 約 {{SIZE:2_body.html}}。Cofit 頁的 Body 約 204KB，上線後完整沒被截斷（2026-10-05 實測）；官方文件沒寫上限。
  • 如果貼上後存不了檔、或發布後頁面下半段不見，就是被截斷了。備案：把圖上傳到 Instapage（官方支援 WebP），程式碼改用圖片網址。

其他備註

  • 字體：從 Google Fonts 載入，只打包頁面用到的字（Cofit 頁三個字重約 392KB；全字集上限約 3.8MB）。LINE、Facebook 內建瀏覽器、Safari、Edge 實測都拿到 woff2。Google Fonts 被擋時改用蘋方體或微軟正黑體，版面不會亂。在 Instapage 後台改到文案（例如表單欄位名稱）時，新字會先用系統字顯示，要回 src/ 改、重產片段才會補上。
  • 縮放：全部尺寸用 rem。Instapage 依螢幕寬度縮放根字級，所以 Body、Footer 的段落會跟編輯器裡的報名區塊一起等比縮放、對齊同一條內容欄（本機在 1440、1024、390 寬實測）。
  • 要改內容時：改 src/ 底下的檔案，再跑 python3 build.py --shots，片段、預覽、這份指南會一起更新。不要直接改 out/，下次產生會被蓋掉。
